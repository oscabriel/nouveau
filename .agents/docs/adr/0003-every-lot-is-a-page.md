# Every lot is a page

The social layer (ADR-0002) gave logs a home on profiles and the activity feed, but the lot itself had no address in the product. Every surface that named a lot linked out to the roaster's own shop, or nowhere: log cards linked the lot name to the roaster's external product URL, feed cards offered "See the lot" (external only), and the roaster page's Lots list was plain text. Logging required the detour Roasters → roaster page → Lots → Log. The owner hit this on the first prod session (2026-09-10) and asked for two things: per-lot action buttons from the feed and roaster pages, and a dedicated page per lot, "like each movie on Letterboxd has its own page."

Decision: the lot is a first-class object page at `/lots/$lotId`, keyed by the `products` row id (same precedent as profile addressing — pretty handles deferred, §13). The page shows the lot's published copy (name, image, description, origin/process/roast level, roaster notes from §14.4), its roaster, and the lot's recent logs with ratings and tasters (capped, newest first). Logging lives on the page; the log form and log cards surface it everywhere a lot is named — feed cards gain a Log action, roaster-page lot rows link their names to the page, and log cards now link the lot name to the lot page instead of the roaster's shop (the shop link survives as "See at {roaster}").

Considered alternatives: inline logging directly from feed cards (works, but the card is about the drop event, not the lot, and it would multiply the form's mounts); or keeping lots addressable only through the roaster page (cheapest, but it repeats the pre-ADR-0002 mistake of giving the product's central object no home). The archived-lot rule carries over unchanged: archived lots resolve fully, so old links never rot.

Consequences: one new public query (`lots.get`, string id in, normalizeId, malformed ids resolve to the "no lot here" page) and a `by_product_and_logged_at` index on `logs`. The page is public — logs are public in this window (§14.1). Lot pages also raise the value of the lot-copy quality bar: junk non-coffee SKUs now get pages too, which makes issue #17 (trim non-coffee products from extraction) load-bearing rather than cosmetic.
